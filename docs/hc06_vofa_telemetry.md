# HC-06 + VOFA+ 跑圈数据采集

## 1. 当前串口分工

| 链路 | STM32F103 引脚 | 波特率 | 用途 |
|---|---|---:|---|
| K230 → STM32 | USART1_RX / PA10 | 115200 | 钢球视觉帧 |
| CH32V307 → STM32 | USART2_RX / PA3 | 115200 | 车辆状态、IMU、轮速帧 |
| STM32 → HC-06 | USART3_TX / PB10 | 115200 | VOFA+ JustFloat |

三条链路互相独立。HC-06 不占用 K230 的 USART1，也不会改变视觉协议。

## 2. 运行接线

### 2.1 CH32V307 到 STM32F103

| CH32V307 | STM32F103 | 说明 |
|---|---|---|
| USART2_TX / PA2 | USART2_RX / PA3 | 交叉连接 |
| GND | GND | 必须共地 |

当前 STM32 不向车辆回传命令，所以 STM32 PA2 可以先不接。

### 2.2 STM32F103 到 HC-06

| STM32F103 | HC-06 | 说明 |
|---|---|---|
| USART3_TX / PB10 | RXD | JustFloat 数据 |
| USART3_RX / PB11 | TXD | 可选，当前程序不使用回传 |
| GND | GND | 必须共地 |
| 电源 | VCC | 按模块底板标注供电 |

注意：

- 带稳压底板、引脚标有 `VCC/GND/TXD/RXD` 的常见 HC-06 成品板通常允许
  VCC 接 5 V，但裸蓝牙核心板只能使用 3.3 V。接线前必须看底板标注，不能仅凭
  “HC-06”名称猜电源电压。
- STM32F103 的 3.3 V TX 可以直接接 HC-06 RXD。
- 不要把 CH32、STM32、K230、HC-06 的多个电源输出脚互相硬并联；只需要共地，
  各模块继续使用已确认的稳定电源。

## 3. 把 HC-06 配置为 115200

推荐先用一个支持 **3.3 V TTL 电平**的 USB-TTL 单独配置 HC-06。

1. HC-06 不与电脑/手机蓝牙配对，保持上电后指示灯快速闪烁。
2. USB-TTL TXD 接 HC-06 RXD，USB-TTL RXD 接 HC-06 TXD，GND 共地。
3. 串口助手选择 `9600, 8 data bits, no parity, 1 stop bit`。
4. 发送 `AT`，不要附加 CR/LF；预期回复 `OK`。
5. 发送 `AT+BAUD8`；经典 linvor 固件预期回复 `OK115200`。
6. 关闭串口，把串口助手改成 115200，再次发送 `AT` 验证。

如果 `AT` 没回复：

- 先确认模块没有处于蓝牙已连接状态；
- 依次尝试“无换行”和模块商家明确要求的行尾；
- 尝试默认 9600；
- 不要盲目连续发送不同波特率设置命令。不同克隆固件的 AT 命令可能不同，应以
  模块实际回复或商家资料为准。

## 4. VOFA+ 设置

1. Windows 蓝牙设置中配对 HC-06，常见 PIN 为 `1234`。
2. 在设备管理器的“端口 (COM 和 LPT)”中确认 HC-06 对应的**传出 COM 端口**。
3. VOFA+ 新建串口连接：
   - 端口：上一步的 COM；
   - 波特率：115200；
   - 数据位：8；
   - 停止位：1；
   - 校验：None；
   - 流控：None；
   - 协议引擎：JustFloat。
4. 当前固定输出 24 个通道，50 Hz。

## 5. JustFloat 通道表

| 通道 | 名称 | 单位/含义 |
|---:|---|---|
| 0 | `time_s` | STM32 本地时间，s |
| 1 | `ball_x` | 钢球位置，px |
| 2 | `target_x` | 目标位置，px |
| 3 | `error_px` | 位置误差，px |
| 4 | `ball_velocity_px_s` | 钢球估计速度，px/s |
| 5 | `p_term_us` | P 项，us |
| 6 | `i_term_us` | I 项，us |
| 7 | `d_term_us` | 速度/D 项，us |
| 8 | `control_out_us` | 总控制偏移，us |
| 9 | `pwm_target_us` | 舵机目标脉宽，us |
| 10 | `pwm_now_us` | 舵机当前脉宽，us |
| 11 | `guard` | 控制保护状态 |
| 12 | `motion_link_valid` | 车辆帧年龄不超过 100 ms 时为 1 |
| 13 | `motion_state` | 0停、1起步、2直行、3左转、4右转、5停车、255故障 |
| 14 | `motion_flags` | 车辆事件和有效性位 |
| 15 | `acc_track_mg` | 车辆指定轨道方向的动态加速度，mg |
| 16 | `yaw_rate_dps` | 横摆角速度，deg/s |
| 17 | `vibration_mg` | 约 100 ms 高频加速度残差均值，mg |
| 18 | `line_error` | 车辆循迹误差 |
| 19 | `left_speed` | 左轮速度 |
| 20 | `right_speed` | 右轮速度 |
| 21 | `turn_command` | `right_target-left_target` |
| 22 | `motion_sequence` | CH32 运动帧序号 |
| 23 | `motion_age_ms` | 最新有效车辆帧年龄，ms |

`motion_flags` 位定义：

- bit0 (`1`)：IMU 有效；
- bit1 (`2`)：车辆已使能；
- bit2 (`4`)：直行命令；
- bit3 (`8`)：转弯命令；
- bit4 (`16`)：起步事件；
- bit5 (`32`)：入弯事件；
- bit6 (`64`)：出弯事件；
- bit7 (`128`)：故障。

## 6. 第一次数据采集顺序

### A. 静态方向验证

暂不让 IMU 参与舵机控制。

1. 车辆静止 5 秒，记录零偏和噪声。
2. 手动让车体向前、向后各推一次，确认 `acc_track_mg` 的正负方向。
3. 手动让车体向左、向右转动，确认 `yaw_rate_dps` 的正负方向。
4. 检查静止时 `motion_link_valid=1`、`motion_sequence` 连续增加、
   `motion_age_ms` 通常小于约 40 ms。

### B. 基准跑圈

保持当前钢球控制参数和 IMU 前馈关闭，连续采集至少 3 圈：

1. 每次从同一发车位置、相近钢球初始位置开始。
2. 启动记录后静止 2 秒，再发车。
3. 完整跑圈，停车后继续记录 2 秒。
4. 每圈保存一个独立 CSV，文件名记录日期、控制参数和圈次。

优先观察以下曲线：

- `error_px` 与 `ball_x`：钢球何时开始向前偏；
- `acc_track_mg`：起步、入弯、出弯时是否出现稳定可重复的脉冲；
- `yaw_rate_dps` 与 `turn_command`：真实转弯和转向命令之间的关系；
- `pwm_target_us`、`pwm_now_us`：控制器是否已到限幅或 slew 限制；
- `motion_flags`：起步、入弯、出弯事件是否覆盖实际扰动时段。

### C. 启用前馈前的判定

至少满足以下条件后，才设计 IMU/转向前馈：

- 三圈中同一类弯道的加速度和横摆信号方向可重复；
- 车辆事件帧没有明显漏报；
- `motion_link_valid` 全程为 1，序号没有大段跳变；
- 已确认“IMU 信号出现”领先于“钢球位置明显偏移”，而不是落后；
- 能区分起步纵向加速度、转弯横摆和车架高频振动。

第一轮不要一边采集一边自动补偿，否则无法建立可靠的基准对照。
